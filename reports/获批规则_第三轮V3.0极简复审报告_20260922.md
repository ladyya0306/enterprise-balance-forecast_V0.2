# 第三轮 V3.0 极简复审报告

2026-09-22。本报告是对[第三轮 V3.0 方案评议 v2](D:/MiniProj/深度学习制作企业产品预测系统/data/research_round2_v4/reports/第三轮V3.0方案评议_20260915_v2_补充复审.md)的精简建议，保留其原有方向，目的是让后续新任务少做重复劳动、能公平比较模型、且从样本到结论都能追溯。**本文未执行 V3 项目创建、资产复制、样本整理、代码修改、训练、生成或考试。** 原样本、旧报告和既有程序均保留，不在本轮删除或重写。

用户已经确定的执行限制与本报告建议分开：Astra 只用于工作安排、任务布置和高难度 bug；其余具体工作未经用户同意不得交 Astra，Terra 与 Luna 负责执行。本报告其余安排只是精简建议，不表示已经验收或获得新的批准。

与 v2 相比，本报告的明确调整有四项：按上述用户限制安排 Terra、Luna 的常规工作；撤除“新考试一定晚于全部旧企业全部目标日期”的硬要求，改按测试目标决定日期隔离；约 80 户、每类约 5 户、70/15/15 都只作起点；将分散验收合并为日期、未来信息、账务、样本隔离和评分五类必要检查。

## 1. 这次保留什么，删减什么

必须保留的不是更多表格，而是能拦住高影响错误的少数检查：实际交易日期与目标日期、未来信息是否混入历史输入、收支和余额账务是否守恒、企业家族是否跨学习/校准/开发测试/新大考串用，以及评分公式和小例子是否一致。日历、收支归集、允许读入字段清单和评分应由同一套已核验程序供各模型调用；发现错误只重做受影响环节，不能因某个模型失败而把全部模型、样本或大考重跑一遍。

建议合并或删除以下重复验收：不再让每个脚本各自造一套英文表名和重复总表；已有程序已经输出且能说明字段、来源和版本的表，直接复用。也不默认逐户长文审读、逐户由 Astra 复算、每一种学习法都强制做基础版和业务版、或为凑类别和户数不停生成企业。相似度、形状、账务与业务标签的共用结果只计算一次、按源 CSV 指纹、工具版本和规则版本缓存；输入未变时读取已有结果，变化时只重算受影响样本及样本对。

现有工具能够给出清单、特征、相似证据、异常和图册时，应保留其中文或既有字段名并加简短字段说明，不能为了形式统一重新造全英文产物。标题、旧形状标签、画像和图册仅作来源备注，不用于决定分类、去重或入组；判断应来自实际 CSV。CSV 彼此冲突时先报异常和证据，不能任选一个相信。平稳、其他、无法判定和证据不足都是允许结论，不能把歧义样本硬塞进走势类别。

## 2. 样本整理：一次算清，人工只判歧义

后续新任务先用统一批处理入口读取实际 CSV，完成一次库存、日期范围、文件指纹、余额与收支特征、实测走势、业务类别覆盖、账务问题和相似度证据。图必须绑定来源 CSV 与日期范围；已有图可复用，只有来源不明或范围不一致时才重画。输出以已有清单和表为基础，最少保存“样本身份、来源、保留或不用理由、处理角色、来源 CSV/图/yaml 路径、来源家族、使用历史和证据路径”等追溯字段即可。

相似度应分级：文件或逐日业务完全一致的，是同一数据来源；已知母样本的改名、缩放或修订版，登记为同一家族；只因长期下降而余额相关高、但业务收支和事件时点不同的，保留并标注机制不同。短记录、日期对齐不足、近乎常数等情况输出不适用或证据不足，不得自动算作低相似而通过。相关系数只触发复核，不能单独删除样本。所有结论写入同一处理表，以后直接复用，不反复阅读长文或重讲同一户的判断。

Terra 负责走势解释、CSV 与既有工具结果冲突、家族归属和业务字段含义等歧义判断；Luna 负责固定命令的批量读取、指纹计算、汇总、绘图和清单更新。Luna 不自行改阈值、删样本或决定入组。常规完成核对由 Terra 进行。普通样本走势歧义由 Terra 直接判断，不得自动升级 Astra；只有高难度 bug 才可例外交 Astra，并附路径、现象、复现条件和已排除项。例外以外如需 Astra，必须先取得用户同意；不得把 Astra 设为默认逐户复审者或例行最终数据复算者。

## 3. 开发与比较：同题、最小对照、保持旧模型不变

旧资料先按独立家族盘点，再作为开发池分配。约 70% 学习、15% 区间校准、15% 开发测试只是起点，不是硬门槛；家族隔离优先于刚好满足比例。样本不足时如实报告实际分配和限制，不通过重复生成凑数。校准只在旧开发池确定区间规则，开发测试用于比较和选型，二者都不能包装成新大考成绩。

基础版和业务版必须使用同一企业、同一预测题目、同一目标日期、同一窗口和同一训练预算，业务版只增加截至预测时已经入账且可知的类别特征。未来交易、未来备注、合同计划、停止经营后的解释和完整未来曲线均不得入模。缺失标签按固定未知规则处理；如确需标签完整子集，两版都用同一子集，并与全样本主结果分开报告。

既有模型应先登记并保留，不能未经盘点就擅自只剩 LSTM 和树模型。最低公平对照是 LSTM 的基础/业务两版，加一种树模型的基础/业务两版；其他已有模型是否参赛，按已登记版本、适配成本和开发池结果决定，不自动把每种方法翻倍。原第一轮模型的权重、标准化、区间参数保持不变；若为接入修正后的日期或收支口径而做输入适配，应明确称为“第一轮模型＋V3 输入适配”，与新训练模型分列，不能把适配后的表现说成原模型原样复现。

所有参赛模型共用整理后的数据、题目、目标、评分程序和结果路径；旧模型的专用输入格式可以保留，不必硬改成与新模型一样。单个训练失败且问题只限该模型时，记录原因并只修复或重跑该版本；若共用数据或评分程序有错，必须重算受影响的预测和结果，不能为省事保留错误数值。简单法、保持原样的旧模型未必有每轮 loss，不能硬补；适用的可训练模型则记录每轮训练误差和验证误差（程序称 loss）、参数、种子和用时。最终比较先按企业等权汇总，同时保留逐题汇总；差距小或按企业波动大时应写证据不足，不以继续扩增新卷来追求胜负。

## 4. 新大考、日期与最少留痕

新大考仍应在开发样本、输入规则、参赛版本和区间规则定稿后，从新生成企业独立产生；技术试产只服务于工具核验，不得事后挑入正式试卷。大考质量检查可看全程 CSV 来查账务、日期、重复和真实走势，但训练、选型阶段只能取得通过/不通过及必要汇总，不能用新卷答案调参或挑模型。新企业与旧开发库、新卷内部均做同规则近复制检查，保留共同业务类别可以，排除的是近复制企业。

约 80 户、重点走势每类约 5 户、70/15/15 都只是预算或盘点起点；“每类 5 户”只是争取有代表，不是通过线。样本很少且证据有限时，以个案说明为主，避免下普遍结论。必须先看实际独立家族、成本、时间、磁盘和合格率，再定稿数量目标、尝试上限和替补顺序。达到上限仍不足就报告缺口，不能不停生成。

本轮主要检验的是**新企业测试**：允许新卷使用已有且可靠覆盖的日历年份，也允许同一年份的跨企业比较。它的硬隔离是每题只读取该企业预测日已经知道的资料；新卷绝不进入模型学习、选型或区间调整，且须排除与旧库的近复制。所有参赛模型在新卷生成前固定。这样的结果应说明为“新企业测试”，不能称为“只用当时以前资料预测后来年份”。只有用户另行要求严格时间前推实验时，才需要把所有学习、早停和校准日期都安排在考试日期之前。本建议不预设考试年份，不引入 2027 年日历工作，也不撤销逐题未来信息检查。

留痕应服务复现而非抄录聊天。建议自动维护三份阶段 Markdown：`01_整理.md`、`02_开发训练测试.md`、`03_新大考.md`。每份包含自动汇总数字、明细文件路径、规则/数据版本、完成项、失败项和下一步；唯一“当前进度”置于项目 README 或状态文件，阶段报告链接至此。运行日志采用追加方式，不覆盖旧记录。训练记录至少包括数据版本、实际日期范围、输入版本、参数与种子、适用模型的每轮训练误差和验证误差（程序称 loss）、用时、失败信息、预测与评分路径、最终选用模型及理由。每个旧模型、简单法和新训练模型的身份与指纹分开登记。

Token 用量不能凭记忆或聊天内容假造：运行环境若能可靠取得则写入来源和数值，不能取得则明确标为“不可得”。同理，不能把看过的报告全文再复制进日志。复制预算程序、生成器和其必要配置、模板、日历、字体等资产时保留资产清单（旧/新路径、指纹、依赖、用途、修改及验收）；代码与统一样本库分开，原样本不删。评测最少保存逐题预测、实际值、方法提供时的上下界、逐户汇总和模型实际状态；滚动题再多也不能被当成同样多的独立企业。直接复用既有逐户汇总，不强加额外统计检验。完整图册和模型详细参数以路径链接，不把它们塞进阶段报告正文。

最终报告沿用现成指标，说明 10 日均和 30 日均的偏差金额、命中率、范围宽度、现成综合评分及用时；次日余额只沿用现成辅助结果，不为它新开发指标。第一轮的 76% 只可作背景，不能代替同题比较。报告还应区分普遍退步与少数企业拖累，说明业务类别相对基础输入的收益，并与原版 LSTM 和简单法比较后给出是否值得继续投入的判断。

## 5. 建议顺序与角色留痕

| 顺序 | 最小动作 | 产物与停止条件 |
|---|---|---|
| 1 | 新任务建目录，复制预算、生成器及必要资产，记录清单 | 代码与样本库分开；未验收不训练 |
| 2 | 用 CSV 和已有工具整理旧开发资料一次 | 清单、异常、相似证据、业务覆盖与处理表齐全 |
| 3 | 修复并验收日期、未来信息、账务、样本隔离、评分共用流程 | 高影响检查通过；只重做受影响步骤 |
| 4 | 先确定开发分组、输入、参赛候选和评分办法，再训练并作开发比较，最后固定最终模型权重和范围规则 | LSTM 与一树模型均有基础/业务同题结果；新卷生成前参赛版本已定稿 |
| 5 | 生成规则定稿后生成并独立检查新大考，封存后统一交卷评分 | 质量合格、访问留痕完整、结果可复算；报告区分普遍退步与少数企业拖累、类别特征的基础收益、相对原版 LSTM 与简单法，并说明是否值得继续投入 |

| 角色 | 常规职责 | 必须留下的记录 |
|---|---|---|
| Luna | 复制核验、批处理、汇总、绘图、追加日志 | 命令/版本、输入输出路径、成功失败的执行记录 |
| Terra | 样本走势与歧义判断、汇总、常规审核、规则适配 | 判断理由、证据路径、阈值或规则变更原因 |
| Astra | 仅在用户已同意的工作安排/任务布置或高难度 bug 中参与 | 例外问题摘要、最小复现、结论及影响范围 |
| 统筹者 | 安排工作、记录需要用户决定的取舍 | 决策时间、依据、适用范围与下一状态 |

## 6. 待统筹安排的事项

统筹者后续只需在真实盘点后安排三项待定工作：哪些旧资料和既有模型纳入开发清单；用户是否另行要求严格时间前推实验；以及在成本与实际合格率明确后确定新卷规模、走势覆盖和重试上限。其余工作可按本报告的最小路径推进，无须默认多模型辩论、重复读长文或新造指标测试。
