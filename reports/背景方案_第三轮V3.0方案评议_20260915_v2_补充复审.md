## 三、样本整理工具：算一次，保存结果，按变化重算

### 3.1 数据和文字冲突时听谁的

先查逐笔流水能否与日余额核对，再从通过检查的日表提取特征。CSV 之间不一致时列为异常，不能武断地相信其中一张。

样本标题保留为来源备注，另存 `measured_shape` 等实测字段，记录原标签与实测结果的差异。新图标题使用实测描述和稳定企业编号。已有图片只有在确认来源 CSV 及日期范围一致后才能复用；不一致就重新绘制。

每户至少保存：记录起止、有效长度、余额中位数/最低值、波动、月均变化、明显转折、收支金额与频率、大额交易集中度、业务类别覆盖率、停止原因。长期下降、U 型、冲高回落等描述必须带时间范围：全程 U 型不等于考试季度发生了反弹。

“平稳”“其他”“无法判定”都是合法结果，不把无法判断的样本硬塞进上升类。缺日期不补成零流水，停止经营不伪造后续记录，平直曲线相关系数无定义时输出“不适用”，不能算作零相似或自动通过。

本次实际发现：`audit_v5b_active_similarity_20260913.py` 会移动候选文件且绑定旧目录；不能直接用作 V3 只读审计。`round2_v4_s5_budgets.py` 写死2025—2026日期和旧输出；`round2_v4_s6_exam.py` 固定旧封存路径并涉及已确认的输入接线缺陷。这些入口必须适配，不能以“旧脚本曾成功退出”代替验收。

### 3.3 相似度先分级，避免错删

建议采用以下处理规则。数值是迁移试运行的起始建议，不是科学通用界线；用旧开发资料核验误报后冻结，不能看新大考成绩再调整。

| 检测结果 | 处理 |
|---|---|
| 原文件哈希相同，或排除企业编号等非业务字段后逐日余额与逐笔业务完全一致 | 计为同一数据的重复来源，保留来源映射；不增加独立企业数 |
| 已知同一母样本的修订/金额缩放版本 | 登记同一家族，不因名字和种子不同而拆分 |
| 对齐后余额形状相关 ≥0.90，且经营净收支相关 ≥0.65 | 沿用旧 S5 数值作为“重点复核线”，核查交易日期/类别/相对金额和共同来源，不直接删除 |
| 只有余额相关高，经营收支、业务类别或事件时间明显不同 | 先保留，记录“形状相似、机制不同”；不能仅因长期下降而剔除 |
| 记录太短、日期对齐不足、序列近乎常数 | 输出“证据不足/不适用”，补查真实交易及来源，不记为低相似度通过 |
| 月内波段或跨周波段多次高度重复 | 使用现有曲线内检测的证据定位；区分合理周期支付与复制模板造成的来回冲落 |

比较同时保留真实日期对齐和企业生命周期对齐两种证据，写明起止、共同长度、是否重采样；不能把不同长度数组直接截短后冒称同口径相关。使用共同区间重新计算统计量。全程与预定考试覆盖区间都要检查，不能靠全年不同掩盖考试区间近复制。

复核确认近复制后，旧库优先整家族分组或按资料完整性选择代表；新大考按考前固定规则排除近复制候选。保留依据和未入选清单，不删除原件、不为了凑人数修改旧样本。若相似簇因链式连接变得很大，标记复核，不自动把整个行业归成同一家族。

### 3.4 固定输出，减少 token 和重复计算

一个统一批处理入口依次调用现有组件，输出：

- `sample_inventory.csv`：独立身份、来源、实际路径、文件指纹、使用历史。
- `sample_features.csv`：数值特征、实测形状及对应时间范围。
- `quality_issues.csv`、`similarity_pairs.csv`、`sample_disposition.csv`：异常、相似证据、处理理由。
- `business_label_coverage.csv`：每户分类来源、未知占比、对齐是否通过。
- CSV 驱动的余额图册和一份 Markdown 摘要。

上述名称是计划产物，尚未生成。结果缓存键由源 CSV 指纹、工具版本和规则配置共同决定；只重算变化的样本和受影响的样本对。运行环境版本也记录在回执中。新规则不得悄悄沿用旧缓存。

Luna 负责运行与输出，Terra 只处理程序标出的歧义和规则缺口，主代理抽查原始 CSV、边界案例和图。人工复核也落入同一记录表，下次直接读取结论和证据，不重复讲一遍分析。

## 四、开发样本与全新大考：替换旧文第3节

### 4.1 旧资料只划分开发职责

第一轮、第二轮、第二轮84户大考等资料，先核对重叠、可访问范围和使用历史。已考试样本可以作为第三轮开发资料，但必须明确它们已被项目使用。不能简单把各轮人数相加。

建议将可用独立家族约按 **70%学习、15%区间校准、15%开发测试** 分配，作为盘点后的起始方案而非已冻结户数。学习组内按时间留出早停验证段；训练目标不能跨进该验证段。按家族整体分配后允许比例小幅偏离，优先避免近复制跨组。

开发测试负责比较和选型，可以反复参考，但因此不能包装成最终成绩。校准组独立用于确定区间，不能把校准组反复当第二个调参测试集。业务类别字典、缺失处理、标准化及相似度规则的数值定稿，都在旧开发资料范围完成。开发池划分不保证旧原模型对这些旧企业未见，其成绩只作开发参考。

### 4.2 新大考只从 V3 新生成企业中产生

先在旧开发资料上完成模型训练、选型、校准及输入规则冻结，再生成正式大考。为迁移工具进行的小批试产应明确登记为技术试产，不能事后挑选其中好用的企业进入正式大考。

顺序建议为：

1. 修复和核验生成、预算、日历、特征、评分链路；必要时少量试产，试产不进大考。
2. 冻结开发样本、业务字典和模型输入；完成模型比较，固定所有参赛版本及区间规则。
3. 冻结大考生成规则、日期、数量目标、资源上限、质量条件、近复制排除与替补顺序，然后生成正式候选。
4. 独立质量检查账务、时间、真实形状、候选内部与旧库相似度；不运行参赛模型预测来决定保留谁。
5. 合格试卷、历史输入与答案分别封存；保存指纹和题目键。训练/选型执行者只获得预测时可用的历史切片。
6. 所有参赛版本先保存完整预测，再统一评分；随后才开放完整图册和逐户分析。

质量检查可以看完整 CSV 和曲线，这是检查试卷；但检查结果不能回流为针对新卷的调参提示。新任务应把质量检查和训练选型分为明确职责及输入清单，记录访问。仅仅换一个任务或给文件改名并不构成技术隔离。程序白名单读取、不同目录和交卷日志一起执行；不能声称已经实现了本轮尚未部署的访问限制。

新生成不等于真实银行数据，也不等于全新生成机制。允许继续使用熟悉的制造业类别和生成器；要排除的是企业近复制，不能要求每个新企业都发明一种新行业。最终结论限定为同一合成数据体系下的新企业泛化表现。

### 4.3 日期、人数、形状构成如何确定

考试起点应晚于所有参赛版本学习、早停和校准使用的目标日期上界，且每题有足够真实历史和完整未来30银行日答案；日历覆盖范围先核验。不能只查流水开始年份，也不能为了对齐直接改写旧交易日期。

尤其要注意：旧资料含延伸至2026年的记录。如果第三轮将截至2026年末的目标都用于拟合或校准，那么新考试起点就需要安排到其后，不能直接照用第二轮2026年第四季度。届时应先确认相应年份的银行日日历来源与覆盖能力；本次没有核验2027年日历，也没有确定新卷年份。

不再默认109户。建议先以 **约80户合格新企业** 作为预算估算目标，试产后给出正式目标、尝试上限、时间和磁盘上限，再冻结；这个人数不是统计精度保证，也未在本轮获准执行。达到上限仍不足时报告实际人数和缺口，不能无限重试或根据模型成绩追加。

总体形状不必等比例，但须考前写清覆盖目的。若希望对长期下降、U型反弹、冲高回落分别评价，建议每类争取至少5个独立企业/家族作探索性观察；不足就按个案说明，5也不足以保证稳定结论。其他类别按实际旧库覆盖和生成可行性分配，最终表必须列“目标数、实际数、长期形状、考试区间形状”，不能给一个笼统标签。

“无心电图、无重复波段”应落实为无明显机械复制且业务合理，不以图是否平滑漂亮作为保留标准。预先按形状覆盖选试卷会改变总体分布，报告中要说明，不能声称这些比例就是银行实际企业占比。

## 五、业务类别在整理阶段准备，两套输入都要可追溯

先把原备注表与逐笔流水按企业内交易编号对齐，再检查时间、方向和金额。检查一对一关系，防止重复连接使金额翻倍。对齐不了的单笔留在未知类并记异常；若账务无法可信重建，先修复或列为不合格，不能猜出标签。

统一为约8—12类是起始建议，实际类别数由学习资料和业务可知性决定。至少保留客户回款、采购、工资、税费、租赁/日常费用、设备、融资、还本付息、股东往来、其他/未知等可解释类别。每户记录类别覆盖的笔数比例和金额比例，第一轮没有备注也不因此直接淘汰；未知本身需要显式表示。

字段分三层保存：

| 层次 | 用途 | 能否默认入模 |
|---|---|---|
| 资料层：全程形状、来源家族、原备注及画像 | 检查、整理和报告 | 不能 |
| 基础历史层：截至起点的余额、收支、频率与公开日历 | 所有新训练基础版本 | 可以，按白名单 |
| 历史业务层：已入账且当时可知的类别金额/次数/间隔 | 业务类别版本 | 通过来源核验后可以 |

不能把未来类别、合同履约计划、停止经营的事后结论或完整曲线形状传入历史特征。月份、季度等公开日期信息可以使用，其计算不能依赖未来是否发生交易。

历史备注若仅来自生成器的准确分类，允许按用户要求研究，但明确标为“理想业务分类条件”；不能冒称已验证真实银行流水分类准确率。整理阶段可以建立完整来源清单，训练所用映射和数据驱动参数只在学习资料上确定，校准、开发测试、新大考出现新词时走固定未知规则。

基础/业务两版必须使用相同企业、题目和目标，否则既换样本又加字段，无法判断收益来自哪里。若因确有输入缺失而另做完整标签子集分析，两版都在相同子集比较，并与全样本主结果分开。

## 七、最少的必要检查与公平比较

必须保留的检查是：指定历史日期逐项一致；改动未来流水/备注/交易日标记后历史特征不变；非银行日已知收支归集守恒；类别连接不重复金额；家族与职责不串；模型和预测指纹可核对；评分用已知小例子及独立复算验证。测试针对这些高影响错误，不为所有文件形式堆大量检查。

新训练的基础版和业务版共同使用修正后的日历与历史收支口径。第一轮原模型保留原权重、标准化、区间参数；迁移时查清其原输入语义是否与 V3 有差异，先做兼容性对照。若用了不同输入语义，报告必须标明“第一轮冻结模型＋V3适配”，不能把适配影响称为重新训练带来的提高；是否增加这一参考版本待兼容核查后决定。

正式参赛数待登记后确定。最小特征对照为基础 LSTM 对业务 LSTM、基础树模型对业务树模型。建议先选 XGBoost 作为固定树模型特征对照，是否另保留 ExtraTrees 等方法在开发阶段确定。基础/业务对照保持同样窗口、训练预算和预先登记的种子安排，不能看新大考成绩挑种子。

10/30银行日日均为主任务，次日余额作为辅助。主任务报金额偏差、命中率、区间宽度及区间综合评分 WIS（同时惩罚范围太宽和漏掉实际值，越低越好）。旧原模型保留原范围，其余方法的范围仅用旧开发池校准；公开各自规则，不暗示不同模型的区间金额宽度完全相同。雷达图仅作展示，不能凭任意缩放后的面积决胜。

总体先按企业计算、再让企业等权汇总，同时报告原逐题汇总，避免窗口多的企业左右结论。重叠滚动题目不能当成互相独立的数千家企业；不确定性按企业/家族为单位估计。若差距很小或波动明显，就说证据不足，不为了得出胜负增加大考尝试。

## 九、新任务交接与执行顺序

后续启动第三轮时创建全新任务，将本文作为唯一方案入口，连同 S6 深诊断、资产清单和旧样本使用历史传入。不能只给一句“按前面执行”，也不把旧项目所有历史授权复制为 V3 当前任务。新任务先建规范目录和简短当前状态文件；不在本任务里悄悄开训。

分工固定：主代理负责范围、取舍、检查口径与最终验收；Terra 负责轻量诊断、工具适配、字段映射和异常解释；Luna 负责按固定命令复制核验、批量计算、绘图和清单整理。Luna 不自行改阈值、删文件或决定哪些企业退出；Terra 不根据大考预测表现修改生成规则。

执行顺序为：**新任务建项目与复制资产 → 工具验收和旧样本实测整理，同时准备业务类别 → 冻结开发角色和输入 → 训练、校准、开发比较及模型冻结 → 全新大考生成与独立质量封存 → 全部交卷后评分、图文分析。** 技术试产放在工具验收阶段且不进正式试卷。每一步保存可复用产物、失败原因和完成状态，失败只重做受影响步骤，避免重跑已完成工作。
